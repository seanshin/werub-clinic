# W.Clinic 병원 실무자 워크그룹 기획안

> 작성일: 2026-05-18
> 대상: 병원/의원 실무자 (의사, 간호사, 행정직, 원무과)
> 플랫폼: clinic.example.org

---

## 1. 현황 분석

### 1.1 현재 대시보드 (구현 완료)

```
┌─────────────────────────────────────────────────┐
│  인사말 + 출근/재택/휴가/퇴근 버튼               │
├─────────────────────────────────────────────────┤
│  공지사항                                        │
├──────────┬──────────┬──────────┬─────────────────┤
│ 결재 대기 │ 오늘 일정 │ 안읽은 DM │ 알림             │
├──────────┴──────────┴──────────┴─────────────────┤
│  서비스: 채널 캘린더 Wiki 전자결재 조직도 근태 연차  │
├─────────────────────────────────────────────────┤
│  병원 동선 위젯 (1F/2F)                           │
├─────────────────────────────────────────────────┤
│  병원 홈 | 관리 | 동선 설정                        │
└─────────────────────────────────────────────────┘
```

### 1.2 병원 실무자가 실제 필요한 것

| 직군 | 핵심 업무 | 현재 지원 | 미지원 |
|------|---------|---------|--------|
| **의사** | 진료 스케줄, 환자 차트 접근, 수술 일정, 당직 | 캘린더, 전자결재 | 진료 스케줄, 수술 보드, 당직표 |
| **간호사** | 병동 환자 현황, 투약 일정, 인수인계, 간호 기록 | 채널, 근태 | 인수인계 보드, 투약 알림, 병동 현황 |
| **원무/행정** | 접수, 수납, 보험 청구, 환자 대기 관리 | 전자결재 | 접수 현황, 수납 대시보드, 보험 청구 |
| **공통** | 공지, 일정, 메시지, 전자결재, 근태 | 전부 | 역할별 대시보드, 긴급 알림, 당직표 |

## 2. 워크그룹 확장 로드맵

### Phase 1: 역할별 대시보드 (2주)

현재 모든 직군이 동일 대시보드를 보고 있음. 역할에 따라 핵심 정보를 다르게 구성.

#### 2.1 의사 대시보드

```
┌─────────────────────────────────────────────────┐
│  좋은 아침이에요, 박의사님  [출근] [당직중]        │
├──────────┬──────────────────────────────────────┤
│ 오늘 진료 │  09:00 김O수 (내과) — 재진            │
│ 12건     │  09:20 이O미 (내과) — 초진            │
│          │  09:40 박O진 (내과) — 검사결과          │
│          │  ...                                  │
├──────────┼──────────────────────────────────────┤
│ 수술 일정 │  14:00 최O영 — 무릎 관절경 (OR-1)     │
├──────────┴──────────────────────────────────────┤
│  병동 담당 환자: 301호 오O택(경과양호) 302호 신O호  │
├─────────────────────────────────────────────────┤
│  결재 2건 | 미읽은 채널 3 | 병원 동선 1F           │
└─────────────────────────────────────────────────┘
```

**필요 데이터 (HIS 제공)**:
- `GET /api/schedule/doctor/:doctorId` — 오늘 진료 목록
- `GET /api/surgery/schedule` — 수술 일정
- `GET /api/ward/patients/:doctorId` — 담당 입원 환자

### Phase 2: 인수인계 보드 (1주)

간호사 교대 시 가장 중요한 기능. Slack 스타일 채널이 아닌 **구조화된 인수인계 양식**.

```
clinic.example.org/handoff

┌─────────────────────────────────────────────────┐
│  인수인계 보드          3층 내과병동               │
│  [야간→주간] [주간→야간]  2026-05-18              │
├─────────────────────────────────────────────────┤
│  301호 오O택                                     │
│  ├ 상태: 경과 양호, 내일 퇴원 예정                │
│  ├ 특이사항: 야간 발열 38.2° → 해열제 투여         │
│  └ 주의: 낙상 위험 (보행 시 보조)                  │
├─────────────────────────────────────────────────┤
│  302호 신O호                                     │
│  ├ 상태: 수술 후 2일차                            │
│  ├ 특이사항: 통증 호소 → 진통제 추가 처방 확인     │
│  └ 주의: 배액량 확인 (4시간 간격)                  │
├─────────────────────────────────────────────────┤
│  [+ 환자 추가]  [인수인계 완료 ✓]                 │
└─────────────────────────────────────────────────┘
```

**구현 방식**:
- 기존 CaféBoard 채널을 "인수인계" 전용 채널로 활용
- 또는 별도 구조화 양식 (환자별 카드 형태)
- HIS에서 환자 기본 정보 자동 채움
- 인수인계 완료 시 양측 서명 기록

**필요 데이터 (HIS 제공)**:
- `GET /api/handoff/template/:wardId` — 병동별 인수인계 양식
- `POST /api/handoff/submit` — 인수인계 제출
- `GET /api/handoff/history` — 인수인계 이력

### Phase 3: 당직/스케줄 관리 (1주)

#### 3.1 당직표

```
clinic.example.org/duty

┌─────────────── 5월 당직표 ─────────────────────┐
│          월    화    수    목    금    토    일   │

│  야간    이의사 박의사 김의사 이의사 박의사 당직B  │
│  응급    김응급 김응급 이응급 김응급 이응급 교대   │
├─────────────────────────────────────────────────┤
│  간호 3F  최NS  이NS  박NS  최NS  이NS  ...     │
│  간호 4F  조NS  한NS  조NS  한NS  조NS  ...     │
├─────────────────────────────────────────────────┤
│  오늘 당직: 박의사 (야간), 김응급의 (응급)        │
```

**구현 방식**:

- 변경 요청 → 전자결재 연동

**필요 데이터 (HIS 제공)**:
- `GET /api/duty/schedule` — 당직 스케줄
- `POST /api/duty/swap-request` — 당직 교대 요청

### Phase 4: 투약/처치 알림 (1주)

간호사의 핵심 업무. HIS에서 투약 스케줄을 받아 알림으로 전달.

```
┌─── 투약 알림 ──────────────────────────────────┐
│  🔴 09:30 (3분 전)  301호 오O택                  │
│     항생제 IV (세파졸린 1g) — 1일 3회             │
│     [투약 완료 ✓]  [사유 입력]                   │
│                                                 │
│  🟡 10:00 (30분 후)  302호 신O호                 │
│     혈압약 PO (아테놀롤 50mg) — 1일 1회          │
│                                                 │
│  ⚪ 11:00  303호 배O연                           │
│     인슐린 SC (노보래피드 10u) — 식전 30분        │
└─────────────────────────────────────────────────┘
```

**구현 방식**:
- HIS 투약 스케줄 API 폴링
- 브라우저 알림 (Notification API)
- 투약 완료 확인 → HIS에 기록 전송
- 미투약 시 에스컬레이션 알림

**필요 데이터 (HIS 제공)**:
- `GET /api/medication/schedule/:nurseId` — 투약 스케줄
- `POST /api/medication/:id/administer` — 투약 완료 기록
- `GET /api/medication/overdue` — 미투약 목록

### Phase 5: 긴급 알림 시스템 (1주)

#### 5.1 Code 알림

```
🚨 CODE BLUE — 302호 신O호
   심정지 의심, 즉시 대응 필요
   [확인] [대응 중] [해제]
   
   발생: 14:23  보고자: 이간호사
   담당의: 박의사 (호출됨)
```

#### 5.2 긴급 수혈/검사 요청

```
⚠️ 긴급 수혈 요청 — 401호 문O식
   혈액형: A+ | Hb: 7.2
   [혈액은행 확인] [수혈 시작]
```

**구현 방식**:
- HIS 긴급 이벤트 → Webhook → Clinic 실시간 알림
- 브라우저 + 모바일 푸시 + 소리 알림
- 알림 확인/대응 상태 추적
- 이력 기록 (의료법 준수)

**필요 데이터 (HIS 제공)**:
- `SSE /api/alerts/stream` — 긴급 알림 스트림
- `PATCH /api/alerts/:id/acknowledge` — 알림 확인
- `GET /api/alerts/history` — 알림 이력

## 6. 우선순위 판단

| 순위 | Phase | 이유 |
|------|-------|------|
| 1 | 인수인계 보드 | 간호사 교대 시 가장 큰 Pain Point, 현재 종이/구두 |
| 2 | 역할별 대시보드 | 전체 사용성 향상, 로그인 직후 필요 정보 즉시 제공 |
| 3 | 당직표 | 월간 스케줄 관리, 교대 요청 프로세스 디지털화 |
| 4 | 투약 알림 | 환자 안전 직결, 미투약 사고 예방 |
| 5 | 긴급 알림 | 생명 관련, 하지만 빈도 낮음 (기존 원내 방송 대체) |
| 6 | 키오스크 | 환자 경험 개선, 직원 업무 부담 경감 |

## 7. 기술 전제
