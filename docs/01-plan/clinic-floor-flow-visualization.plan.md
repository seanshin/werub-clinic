# 병원 동선 시각화 개선 방향성 기획 (clinic.example.org/floor)

> 목표: 평면도 위 동선의 **흐름을 애니메이션으로 표현**하고, **병목·이슈(원활하지 않은 부분)를 직관적으로 강조**한다.
> 부가: 이를 위해 **HIS에 추가로 요청할 데이터**를 정의한다.

---

## 1. 현황

**렌더링**: `FloorCanvas`(Canvas 2D) — 존(zone) 사각형 + 엔티티를 **존 단위로 군집** 표시 + heatmap 오버레이. `fetchStats` 폴링.

**현재 HIS 가용 API** (`/api/clinic/his/floor/*`, 메인앱은 `[...path]` 캐치올 프록시 → 새 엔드포인트 자동 통과):

| 엔드포인트 | 데이터 |
|-----------|--------|
| `plans` | 층 목록 |
| `zones/{floor}` | 존 + bounds(x,y,w,h) |
| `entities/{floor}` | 엔티티(type, **zoneId 단위 위치**, status, waitMinutes, arrivedAt, dept) |
| `stats/{floor}` | 존별 currentCount/capacity/**avgWait·maxWait/congestion(low~critical)** |
| `stats/{floor}/summary` | **bottleneck 1곳** + 층 요약 |
| `history/{entityId}` | **단일** 엔티티 존 경유 이력(movements: enter/leave/duration) |

**한계**: ① 엔티티가 **존 단위**(정밀 x/y 없음) ② 흐름은 **개별 엔티티 history만**(존간 집계 OD 없음) ③ **폴링 스냅샷**(실시간 이벤트 없음) ④ 존 **인접/경로(복도·출입구) 없음** ⑤ "원활하지 않음"의 **기준(기대치) 없음**.

---

## 2. 개선 방향성 (3축)

### A. 흐름(Flow) 애니메이션
- **존간 흐름선(flow lines)**: 존A→존B 이동량을 곡선/화살표로. **두께=이동량**, **흐르는 파티클**(움직이는 점)로 방향·속도 표현.
- **엔티티 이동 보간**: 스냅샷 간 위치 변화를 easing 애니메이션 + **잔상(trail)**으로 "움직임"을 표현 (Phase 1은 존 중심 간 보간).
- **OD 흐름맵 / Sankey**: 시간대별 존간 전이를 Sankey 또는 흐름 굵기로 집계 표시 → 주 동선 패턴 파악.

### B. 병목·이슈(원활하지 않은 부분) 강조
- **병목 존 펄스**: congestion=high/critical 존을 **맥동 애니메이션**(대기시간 비례 강도/속도), 빨강 계열.
- **정체 흐름 표현**: 흐름선이 느려지거나 적체된 구간은 **색·속도 변화**(빨강·저속), 역류/대기열 시각화.
- **이슈 배지/오버레이**: 용량 초과(count>capacity), 대기 임계 초과, 흐름 중단, 응급 유입 등을 아이콘+툴팁으로. 클릭 시 상세.
- **기대 대비 편차**: 존별 목표(SLA) 대비 실제 대기/처리량 편차를 색으로 → "원활/지연"을 **자동 판정**.

### C. 실시간성
- 폴링 → **이벤트 스트림(SSE)**: 존 진입/이탈 이벤트 수신 → 끊김 없는 부드러운 애니메이션.
- **타임랩스/리플레이**: 과거 N시간 동선 재생으로 혼잡 패턴·원인 분석.

## 3. HIS 추가 요청 데이터 (핵심)

> 메인앱 프록시는 캐치올이라 **HIS 측 신규 엔드포인트 + 프론트**만 추가하면 됨.

| # | 요청 항목 | 용도 | 우선순위 |
|---|-----------|------|:---:|
| 1 | **존간 전이 집계(OD)** `GET /floor/flows/{floor}?from&to&window` → `[{fromZone, toZone, count, avgMinutes}]` | 흐름선·Sankey·주동선 | ⭐⭐⭐ |
| 2 | **실시간 이동 이벤트(SSE)** `GET /floor/events/{floor}` → `{entityId, fromZone, toZone, at, type}` | 부드러운 실시간 애니메이션 | ⭐⭐⭐ |
| 3 | **존 토폴로지(인접·경로)** `GET /floor/topology/{floor}` → `edges[{a, b, polyline, distance}]`, 출입구 좌표 | 흐름선을 **실제 복도 경로**로 라우팅 | ⭐⭐ |
| 4 | **층 단위 이력 일괄** `GET /floor/history/{floor}?from&to` (현재는 단일 entityId만) | 리플레이·OD 산출 | ⭐⭐ |
| 5 | **존별 기대치/SLA** 존 목표 대기·처리량(or 시간대 baseline) | "원활하지 않음" **자동 판정** | ⭐⭐ |
| 6 | **흐름 차단/이슈 컨텍스트** 응급·격리·장비고장 등 사유 태그 | 이슈 표현에 의미 부여 | ⭐ |
| 7 | **엔티티 정밀 좌표(선택)** RTLS 보유 시 존 내 x/y 또는 진입·이탈 지점 | 이동 보간 정밀도↑ | ⭐ |

> 1·2번이 "흐름 애니메이션"의 핵심, 5번이 "이슈 자동 감지"의 핵심.

## 4. 단계별 로드맵

| Phase | 범위 | HIS 의존 |
|-------|------|:---:|
| **P1 (즉시, 현 데이터)** | 존 펄스/병목 강조 강화, 엔티티 점 보간 이동 + trail, heatmap 고도화, 이슈 배지(용량/대기 임계) | ❌ 무변경 |
| **P2 (흐름)** | OD 흐름선·파티클·Sankey, 층 history 리플레이 | ✅ #1, #4 |
| **P3 (실시간·자동감지)** | SSE 실시간 애니메이션, SLA 기대 대비 자동 이슈/지연 판정, 경로 라우팅 | ✅ #2, #3, #5 |

## 5. 기술 메모

- 렌더링: Canvas 2D 유지(현 FloorCanvas) + `requestAnimationFrame` 루프로 파티클/펄스. 고밀도 시 WebGL(PixiJS) 검토.
- 파티클 흐름: 흐름선 폴리라인을 따라 t∈[0,1] 파티클 다수, 속도∝평균소요의 역수, 색∝정체도.
- 성능: 이벤트 SSE는 hisProxy에 SSE 패스스루 필요(현 proxy는 JSON 일괄 — 스트리밍 분기 추가 검토).
- 접근성/안전: 의료 화면 — 색만이 아닌 아이콘/수치 병기, 색약 대응 팔레트.

## 6. 권고

- **P1은 HIS 변경 없이 즉시 착수 가능** (체감 개선 큼: 병목 펄스 + 이동 애니메이션 + 이슈 배지).
- P2·P3는 **HIS 팀에 #1(OD)·#2(events SSE)·#5(SLA) 우선 요청**. 위 표를 그대로 전달하면 됨.
